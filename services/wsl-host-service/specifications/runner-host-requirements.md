# Original runner host composition
The existing host record is the sole machine-configuration carrier. CI currently has no registered runner for its private consumer. The old retired superrepo registration confers no scope, labels or capacity.

- RH-1. An optional linux.runnerHost component shall delegate only the original pinned runner supplier's observe/apply APIs through the existing wsl-host plan/apply CLI.
- RH-2. The record shall bind canonical source module and SHA256, actual owner UID, host section and the original ci-runner-host-parameters@1 parameters before supplier import or invocation.
- RH-3. Each runner's mutable root and explicit archive destination shall remain under that host section's typed data custody with no symlink escape or home fallback.
- RH-4. Component plan shall change no machine file, service, registration or credential.
- RH-5. Component apply shall operate as the record's actual unprivileged owner and shall leave every unrelated Linux, Windows, maintenance, timer and quarantine component untouched.
- RH-6. The structured GitHub supplier shall receive actual scoped runner metadata, and shall not treat labels or a local file as proof of registration or availability.
- RH-7. A second converged component apply shall invoke no configuration or registration operation.
- RH-8. Actual activation shall follow independent source receiving, fresh host byte/inode/backing and memory admission, an exact reviewed-source job binding and original queued-job reconciliation.
